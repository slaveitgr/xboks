# Remote Play integration

The shell entry follows the supplied 416 × 580 profile dialog (`36009.png`). Its wording distinguishes the launcher profile from the separate Microsoft web sign-in: it does not promise that the profile button authenticates the player automatically.

`src/main/remote-play.ts` now attaches an isolated Electron `WebContentsView` **inside the existing launcher window**, below a trusted 64 px React toolbar. It does not create a separate browser/player window. `RemotePlayHost` provides console-home navigation, history Back, reload, close, loading and recoverable load-error surfaces. “Ready” means that the official page loaded; it does not assert that a console was found or a streaming session connected.

The embedded service remains Microsoft's [console Remote Play client](https://www.xbox.com/play/consoles). Microsoft controls its sign-in, console list and WebRTC streaming. This differs from the original Windows app's native `GameStreamView` and service contracts; see [the static ownership trace](reference/remote-play-ownership.md). Native Xbox console discovery, wake/setup commands and streaming protocol have not been reimplemented in xboks. Xbox One X account/console streaming acceptance is still required.

The view has no launcher preload, Node integration or launcher account tokens. A distinct persistent Chromium partition retains Microsoft web sign-in independently of the launcher. Top-level navigation accepts HTTPS Xbox domains and explicit Microsoft authentication hosts; credentials in URLs and custom ports are rejected. Popups are denied, with approved sign-in navigation reused in the same isolated view. Normal Chromium TLS and origin checks remain enabled.

Only the exact `https://www.xbox.com` **main frame under `/play` or a locale-prefixed `/play` route** can receive fullscreen and local-network permissions. Login pages and child frames cannot receive those grants. Microphone, camera, display capture, loopback-network and other permissions remain denied. The current [Electron session documentation](https://www.electronjs.org/docs/latest/api/session#sessetpermissionrequesthandlerhandler) documents both `local-network` and `local-network-access`; installed Electron 44 type declarations were checked too. These grants enable the official player's LAN requests, not a claim that a console connection was tested.

The web player owns ordinary Escape and controller B while it has focus. Ctrl + F6 returns keyboard focus to trusted host controls; Escape there closes Remote Play. Native F11 delegates to the launcher's coordinated fullscreen handler when supplied. Native-view focus makes the launcher's `document.hasFocus()` false, so its gamepad poller does not handle gameplay behind the stream. Hiding the native view for Game Bar returns focus to the trusted window; restoring it preserves the existing player. Resizing preserves the toolbar boundary. Closing destroys the child renderer, detaches the view and releases its display-sleep blocker; a load error retains the host for explicit retry. Stale navigation/control responses cannot reopen a closed host.

Validation on 2026-10-21: 11 manager tests and 4 renderer observer/status tests; isolated Electron renderer fixture with 14 interaction checks and three Greek previews. A separate native Electron fixture replaces the HTTPS route with local test HTML to verify the actual child-view, security and focus lifecycle without Microsoft requests, account access, console discovery, media capture or game streaming. Its output is `outputs/remote-play-native-2026-10-21/native-remote-play-report.json`. The renderer previews are host fixtures, not screenshots of a connected Xbox session.
